# «Снежная почта» — лендинг

Статический адаптивный лендинг с защищённым серверным обработчиком заявок для Bitrix24.

## Запуск

```powershell
cd C:\Users\asmaga\Documents\Skazka\snow-mail-landing
python -m http.server 8080
```

Открыть `http://127.0.0.1:8080/`.

Автотест `tests/qa_landing.py` использует отдельный локальный порт `8091`. Если порт занят, адрес можно переопределить через `SNOW_MAIL_BASE_URL`.

## Форма и Bitrix24

Клиент на основном домене и зеркале GitHub Pages отправляет JSON на единый endpoint `https://parkskazka.ru/snow-mail/api/lead`. Обработчик создаёт лид Bitrix24 и возвращает успешный ответ только после получения ID лида.

В лид передаются:

- имя, телефон, желаемая дата, количество и возраст детей, комментарий;
- подтверждение согласия, адрес страницы и referrer;
- `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`.

Webhook Bitrix24 хранится только на сервере в переменной `BITRIX_WEBHOOK_URL`. Его нельзя добавлять в `config.js`, HTML, Git или логи.

Защита обработчика: строгая проверка Origin, CORS для публичного лендинга, honeypot, контроль времени заполнения, ограничение частоты, request ID и защита от повторной отправки.

После подтверждённой отправки клиент вызывает событие `snowmail:lead-success` и добавляет в `dataLayer` событие `snow_mail_lead_success` без персональных данных.

## Локальные проверки

Браузерный тест с mock-ответом CRM:

```powershell
python tests/test_form_bitrix.py
```

Интеграционный тест PHP-обработчика с локальным mock Bitrix24:

```powershell
python tests/test_lead_endpoint.py --php C:\path\to\php.exe
```

Рабочая CRM при этих проверках не вызывается.

## Границы релиза

- Публикация выполняется через GitHub Pages из ветки `main`.
- Изображения сгенерированы как нейтральные постановочные сцены; они не изображают реальные аттракционы или территорию Парка Сказка.
- Основной production URL: `https://parkskazka.ru/snow-mail/`.
- Перед рекламным запуском нужно выполнить один явно помеченный тестовый лид и проверить поля в Bitrix24.
